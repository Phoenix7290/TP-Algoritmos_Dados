## Exercício 9: Comparação entre Build-Heap e inserção incremental

Este exercício mostra a diferença entre duas formas de construir uma heap:

- abordagem top-down: insere um elemento por vez;
- abordagem bottom-up: aplica `build_heap` em um array já existente.

## Comparação prática

| Critério | Inserção incremental | Build-Heap (otimizado) |
| --- | --- | --- |
| Abordagem | Começa com heap vazia e insere um por um. | Organiza um array pronto de baixo para cima. |
| Operação base | `sift-up` (subir o elemento). | `sift-down` (descer o elemento). |
| Complexidade | $O(n \log n)$ | $O(n)$ |
| Número de trocas | Maior, porque elementos na base podem subir bastante. | Menor, porque a maioria dos nós faz poucas trocas. |

## Discussão dos resultados

Na inserção incremental, cada novo elemento pode precisar subir até a raiz. No pior caso, isso custa $O(\log n)$ por inserção. Como o processo é repetido para todos os elementos, o custo total cresce para $O(n \log n)$.

No `build_heap`, a situação é diferente. Os nós folha já satisfazem a propriedade de heap, então não precisam de correção. O trabalho fica concentrado nos níveis mais altos da árvore, que são poucos. Por isso, o custo total se mantém linear.

## Conclusão

Para construir uma heap a partir de dados já disponíveis, `build_heap` é a melhor escolha. A inserção incremental só faz mais sentido quando os dados chegam aos poucos, em tempo real.

## Resumo final

- `build_heap` é mais eficiente para inicialização em lote.
- inserção incremental é útil quando os dados chegam gradualmente.
- a diferença vem da quantidade de trabalho feita em cada nível da árvore.
