# Exercício 1 - Motivação computacional para uso de Heaps

## 1. Problema computacional real com priorização dinâmica

**Problema**: Gerenciamento de tarefas em um sistema operacional ou em um servidor de processamento de jobs (ex: scheduler de um cluster como Kubernetes, Apache Airflow ou um simulador de eventos discretos).

O sistema recebe constantemente tarefas com diferentes **prioridades** (urgência, deadline, importância do usuário, consumo estimado de CPU, etc.). É necessário sempre executar primeiro a tarefa de maior prioridade, e novas tarefas podem chegar a qualquer momento (priorização dinâmica).

## 2. Justificativa formal para o uso de Binary Heap

Uma **Max-Heap** (ou Min-Heap dependendo da convenção) implementa perfeitamente uma **Priority Queue** porque:

- Permite inserção de novas tarefas em **O(log n)**.
- Permite extração da tarefa de maior prioridade (**extract-max**) em **O(log n)**.
- Acessa o elemento de maior prioridade (**peek**) em **O(1)**.

Essas garantias são ideais para sistemas onde o número de tarefas pode ser grande (milhares ou milhões) e a taxa de chegada/extracção é alta.

## 3. Comparação com outras estruturas

| Estrutura                  | insert          | extract-max     | peek     | Vantagens                          | Desvantagens                          |
|---------------------------|-----------------|-----------------|----------|------------------------------------|---------------------------------------|
| **Binary Heap**           | O(log n)        | O(log n)        | O(1)     | Bom equilíbrio, boa localidade     | Não suporta diminuição de prioridade facilmente |
| **Lista ordenada**        | O(n)            | O(1)            | O(1)     | Simples                            | Inserção muito lenta                  |
| **Árvore BST balanceada** (ex: AVL, Red-Black) | O(log n) | O(log n)        | O(1)     | Ordenação completa                 | Maior overhead constante, mais complexa |
| **Fila simples (list)**   | O(1)            | O(n)            | O(n)     | Muito simples                      | Extract-max péssimo                   |

A heap vence na maioria dos cenários de **prioridade dinâmica** por oferecer o melhor trade-off entre as operações críticas.

## 4. Análise de Complexidade (Big O)

- **Inserção de tarefa**: O(log n)
- **Extração da tarefa de maior prioridade**: O(log n)
- **Verificar próxima tarefa (peek)**: O(1)
- **Construção inicial a partir de n tarefas**: O(n) (usando heapify)

No pior caso, um scheduler processando 10⁶ tarefas terá operações rápidas e previsíveis, diferente de uma lista ordenada que degeneraria para O(n) por inserção.
