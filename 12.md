## Arquitetura e justificativa

### Estrutura de dados

- Representação: array dinâmico (lista Python). O mapeamento índice→filhos usa $2i+1$ e $2i+2$, o que facilita acesso e updates em O(1).
- Tipo: Max-Heap — cada nó pai tem valor >= dos seus filhos; a estrutura é uma árvore binária quase completa.

### Escolhas algorítmicas

- Build-Heap (Floyd, bottom-up): constrói a heap em-place em O(n). Esta abordagem é preferível a n inserções sucessivas (O(n log n)) quando há um array inicial grande.
- Sift-down: implementado de forma recursiva por clareza; a versão iterativa é equivalente em complexidade e evita recursão em casos extremos.

### Complexidades principais

- Build-heap: O(n).
- Insert (sift-up): O(log n) no pior caso.
- Extract-max (sift-down): O(log n) no pior caso.
- Peek: O(1).
- Busca linear (`contains`): O(n) — a heap não ordena nodos de diferentes subárvores.
- Delete (remoção arbitrária): O(n) para localizar + O(log n) para restaurar = O(n).

### Propriedades formais e correção

- Propriedade de ordem: mantida localmente por operações de sift-up / sift-down; restaurar a propriedade localmente após troca garante correção global.
- Propriedade estrutural: ao representar a heap em array preservamos a completude da árvore; a altura é $\lfloor \log_2 n \rfloor$.

### Observações práticas

- Implementações em arquivos separados priorizam clareza para ensino e testes; para uso em produção, um único módulo com API limpa (`insert`, `extract_max`, `build_heap`) é recomendado.
- A escolha recursiva do `sift_down` é segura na prática (heaps são balanceadas), mas troque por uma versão iterativa se for necessário suportar entradas enormes ou ambientes com limites de recursão restritos.
- O algoritmo é in-place e com consumo de memória O(1) adicional além do array.

### Uso típico

- Filas de prioridade, algoritmos de seleção (top-k), e heapsort parcial são aplicações naturais.
